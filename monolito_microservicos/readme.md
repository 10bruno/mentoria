# Monólito e Microserviços

Material sobre a evolução de arquiteturas de software, partindo de aplicações monolíticas até arquiteturas baseadas em microserviços.

O conteúdo aborda os principais conceitos, características e trade-offs de cada modelo, mostrando que a evolução arquitetural deve acontecer de acordo com necessidades reais e não simplesmente pela adoção de novas tecnologias.

## Conteúdo

- Evolução das arquiteturas de software
- Monólitos e monólitos modulares
- Big Ball of Mud e importância da modularização
- Conceitos e arquitetura de microserviços
- Trade-offs entre monólitos e microserviços
- Complexidade de sistemas distribuídos
- Critérios para decomposição de um monólito
- Strangler Pattern e migração incremental
- Quando evitar novos microserviços
- Identificação de fragmentação excessiva
- Critérios para consolidar serviços
- Framework para separar, manter ou unir serviços

## Objetivo

Fornecer uma visão prática para avaliar decisões arquiteturais, entendendo quando manter uma arquitetura simples, quando distribuir responsabilidades e quando simplificar novamente.

> Arquitetura não é um destino final. É uma decisão evolutiva guiada pelo contexto.
